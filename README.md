## Почему создан этот форк: реальные жалобы и как они решены

Оригинальный веб-клиент ZCode (`zcode --web`) создавался разработчиками как прямой порт десктопного Electron-приложения под мышь и большой монитор. При попытке реально пользоваться им со смартфона (iPhone PWA по домашней сети) всплыл целый пласт блокирующих дефектов.

Ниже собраны **реальные проблемы и жалобы**, возникшие в ходе боевого тестирования, и то, как каждая из них была устранена в этом форке:

---

### 1. Ввод текста и клавиатура

#### 🔴 Жалоба: *«Пролаги бывают, когда пытаешься слово исправить, которое частично напечатано»*
* **Что было не так в оригинале:** На каждый введённый символ или backspace композер синхронно вызывал `updateComposerContent` -> обновлял состояние родителя -> перерендеривал **всю панель сессии целиком** (более 4000 строк React-кода). Кроме того, плагин ввода на каждое событие `beforeinput` синхронно сканировал всё DOM-дерево через `getAllTextNodes()`, а `TextContentPlugin` дважды прогонял сериализацию Markdown AST. На мобильном Safari стирание или исправление опечатки намертво вешало поток WebKit на 1–2 секунды.
* **⚡ Как решено:**
  1. Черновик отвязан от покадрового рендера: сохранение текста черновика переведено на дебаунс 350 мс.
  2. Обновление состояния кнопки «Отправить» срабатывает только при переходе `empty ↔ non-empty`, не дёргая родительские компоненты внутри набранного текста.
  3. В плагины ввода добавлен fast-path guard: пропущен тяжелый обход DOM при обычном вводе букв, добавлен гард на композицию символов (`editor.isComposing()`).
  4. Кэширован `lastReportedTextRef` без двойной сериализации AST. Набор текста и исправление опечаток в Safari стали абсолютно плавными.

#### 🔴 Жалоба: *«При открытии каждый раз открывается клавиатура на пол-экрана, можно это убрать?»*
* **Что было не так в оригинале:** В объекте управления фокусом флаг мобильного экрана был захардкожен в `isMobileViewport: false`. На каждый mount страницы, открытие черновика и переход между сессиями код дёргал десктопный `inputApi.focus()`. На iOS экранная клавиатура моментально вылетала на пол-экрана, закрывая диалог и требуя ручного скрытия.
* **📱 Как решено:** Реализован детектор coarse-touch устройств (`isMobileTouchViewport` для тач-экранов ≤767px). Автофокус при старте и переключениях корректно возвращает `"skip"`. Клавиатура выезжает **только тогда, когда пользователь сам тапает по полю ввода**.

### 2. Мобильная вёрстка и тач-управление

#### 🔴 Жалоба: *«Правый side-pane делил экран 50/50 на телефоне — всё ещё сжимает основное окно в момент анимации, сплющивает и перекашивает чат»*
* **Что было не так в оригинале:** Панель инспектора кода, диффов и браузера участвовала в десктопной `ResizablePanelGroup`. При её открытии библиотека меняла `flex-grow` соседнего контейнера чата, ужимая его до узкой полоски шириной ~100px.
* **🎨 Как решено:** Внешний контейнер панели выведен из flex-потока на мобильных (`[data-panel]#browser { flex: 0 0 0px !important }`), а внутренний контейнер переделан в полноценный оверлей-шторку (`w-[min(92vw,560px)]`) с аппаратной GPU-анимацией выезда (`transform: translateX`), затемняющим backdrop'ом и кнопкой закрытия. Чат под шторкой всегда сохраняет 100% ширины.

#### 🔴 Жалоба: *«Сайдбар-drawer: авто-скрытие не сработало, и нет кнопки закрытия»*
* **Что было не так в оригинале:** Авто-скрытие сайдбара висело на смене `activeTaskId` — при повторном клике по уже открытой задаче сайдбар оставался открытым. При этом открытый сайдбар перекрывал гамбургер в шапке, а собственной кнопки закрытия не имел.
* **🚪 Как решено:** Закрытие drawer'а переведено на само действие тапа по любому элементу навигации (`collapseSidebarOnMobileNav`), а внутри сайдбара добавлен явный крестик закрытия (`XIcon`), видимый только на тач-экранах.

#### 🔴 Жалоба: *«Окно уезжает за экран при скролле, и зумит экран при фокусе»*
* **Что было не так в оригинале:** В iOS Safari срабатывала нативная «резинка» (rubber-band bounce), утягивая весь документ за пределы экрана. А поля ввода со шрифтом меньше 16px заставляли Safari автоматически масштабировать страницу при каждом фокусе.
* **🧈 Как решено:**
  1. На уровне `html, body` заданы `overflow: hidden`, `touch-action: manipulation` и `overscroll-behavior: none` — скроллится только внутренний список сообщений.
  2. Шрифт всех полей ввода на экранах ≤767px зафиксирован на `16px !important`, включён `viewport-fit=cover`.
  3. Для ленты диалога (`ConversationTimeline`) включён аппаратный momentum-скролл iOS (`-webkit-overflow-scrolling: touch`), изолированы стили строк (`will-change: transform`, `contain: layout style`), а буфер оверскана увеличен до 12 строк.

#### 🔴 Жалоба: *«Кнопки копирования/редактирования под сообщениями не нажать, а детали ошибок тулов не открываются по тапу»*
* **Что было не так в оригинале:** Кнопки действий над сообщениями были спрятаны за CSS-классом `opacity-0 group-hover:opacity-100` (на тач-экранах нет hover). Ошибки вызова инструментов выводились исключительно в тултипе Radix UI, который открывается только при наведении курсора мыши.
* **👆 Как решено:** Действия над сообщениями сделаны постоянно видимыми на устройствах без мыши через `@media(hover:none)`. Тултип ошибки заменён на интерактивный `Popover`, открывающийся по обычному тапу.

### 3. Сеть, файлы и уведомления

#### 🔴 Жалоба: *«Прикрепление файлов: значок "!" появляется сразу при выборе фото из галереи»*
* **Что было не так в оригинале:** Загрузчик вложений требовал вычисления SHA-256 через WebCrypto API (`crypto.subtle.digest`). По спецификации браузеров, WebCrypto доступен **только в secure context (HTTPS)**. При открытии веб-клиента по локальному IP домашней сети (`http://192.168.x.x:3040`) браузер отключает `crypto.subtle`, выбрасывая фатальную ошибку `fault.attachment.checksumUnavailable` ещё до отправки файла на сервер. Аналогично ломалось копирование в буфер обмена (`navigator.clipboard`).
* **📎 Как решено:** Написан легковесный чистый JavaScript fallback для SHA-256, работающий в любом контексте. Для буфера обмена добавлен полифилл на базе `document.execCommand('copy')`. Фотографии и вложения теперь стабильно загружаются по обычному локальному HTTP.

#### 🔴 Жалоба: *«Уведомления: сидеть у экрана и ждать завершения задачи неудобно, а Tailscale отпал из-за своего VPN на iOS»*
* **Что было не так в оригинале:** На iOS можно держать активным только один VPN-слот (нужен для личных целей, Tailscale отпал). Браузерный Web Push в Safari жестко требует валидный HTTPS-сертификат, который по локальному IP не получить.
* **🔔 Как решено:** Реализован независимый **ntfy-мост**. Сервер сам делает прямой HTTP POST на `https://ntfy.sh/<секретная_тема>` при завершении или ошибке задачи (по сигналу `background_terminal`). На iPhone ставится бесплатное приложение **ntfy** из App Store — звук и пуш приходят на телефон даже при закрытом ZCode и заблокированном экране, без VPN и без SSL-сертификатов.

### 4. Архитектура сервера, сессии и локализация

#### 🔴 Жалоба: *«При выгрузке приложения из памяти PWA сбрасывается на пустой черновик»*
* **Что было не так в оригинале:** Механизм восстановления сессий (`usePaneSessionPersistence`) срабатывал только при `reload` страницы. Когда iOS выгружает фоновую вкладку PWA из памяти, повторный вход регистрируется как `navigate` (холодный старт). Код принудительно создавал новый черновик и стирал ключ последней сессии из памяти.
* **💾 Как решено:** Добавлен флаг `restoreOnFreshLoad: !isDesktop`. На мобильных устройствах при любом холодном старте PWA читает `localStorage` и мгновенно восстанавливает последнюю открытую беседу.

#### 🔴 Жалоба: *«По плюсику в разделе Задачи чат появляется в проекте или теряется, а default workspace не открыть»*
* **Что было не так в оригинале:** Веб-сервер принимал только один рабочий путь в `ZCODE_SERVER_WORKSPACE`. Вкладка «Задачи» (общие беседы) живет в воркспейсе `default` (`~/.zcode/workspace/default`), который веб-сервер вообще не сообщал клиенту. Списки conversations в десктопе обслуживались недоступным в вебе сервисом `windowControllerService`.
* **📁 Как решено:** 
  1. `ZCODE_SERVER_WORKSPACE` научен принимать список путей через разделитель `;`.
  2. Воркспейс бесед выведен в сайдбар полноценным проектным рядом «Задачи».
  3. Серверные пути нормализуются через `realpathSync.native` (устранено падение `assert fs-event` в libuv из-за Windows 8.3 путей вроде `ADCC~1`).

#### 🔴 Жалоба: *«Модель по умолчанию постоянно сбрасывается на мёртвый дефолт при переходе между проектами»*
* **Что было не так в оригинале:** История выбора модели сохранялась строго per-workspace (`zcode-model-selection-recent-v1:<workspaceKey>`). При переходе из проекта в «Задачи» запись отсутствовала, и интерфейс откатывался к нерабочему системному дефолту.
* **🎯 Как решено:** Внедрен глобальный ключ `zcode-model-selection-recent-global-v1`. Любой выбор модели или уровня размышлений (thought) в меню селектора сразу сохраняется глобально и подставляется во всех новых чатах и воркспейсах.

#### 🔴 Жалоба: *«Агенты не видят MCP-инструменты в веб-версии, а список серверов в настройках пуст»*
* **Что было не так в оригинале:** 
  1. При старте сессии stdio MCP-серверы (gce, exa) подключаются 3–5 секунд. Если агент стартовал раньше, runtime навсегда выставлял флаг `mcpToolsRegistered = true` с 0 инструментов, блокируя последующие попытки.
  2. В UI-хранилище `resolveMcpDirectoryService` для локального веб-воркспейса возвращал заглушку с пустым списком серверов.
* **🔌 Как решено:** В рантайм добавлен механизм `collectLateArrivals` с дорегистрацией инструментов на последующих ходах и сбросом кэша модели. В веб-клиенте подключен RPC-канал `mcpSyncService`, тумблеры серверов корректно отображаются в настройках.

#### 🔴 Жалоба: *«Нужен нормальный русский язык без вылезаний за границы»*
* **Что было не так в оригинале:** Оригинал поддерживал только английский и китайский языки. Быстрые авто-переводы ломали верстку, обрезали слова и давали несовместимый разнобой терминов.
* **🌐 Как решено:** Выполнен полный профессиональный перевод всех 5 472 строк интерфейса через Claude Opus с единым инженерным глоссарием. Добавлена кнопка переключения языка («Ру») в подвале сайдбара, а тип `ru-RU` прописан в схемах валидации сервера `@zcode/shared`, исключая ошибки сохранения настроек.

## Быстрый старт

### Вариант 1. Установка готового дистрибутива (Рекомендуется)

Установка одной командой на машину, где запущен Node.js (Linux, macOS, WSL, Git Bash):

```bash
curl -fsSL https://github.com/v9n9yphb67-ui/ZCode/releases/download/v3.14.0-web/install.sh | sh
```

Запуск сервера на всю локальную сеть:
```bash
zcode --web --host 0.0.0.0 --port 3040
```

Сервер выведет адрес для подключения:
```
http://192.168.x.x:3040/?token=YOUR_TOKEN
```

### Вариант 2. Запуск из исходников репозитория

```bash
# Клонирование форка
git clone -b iphone-web https://github.com/v9n9yphb67-ui/ZCode.git
cd ZCode

# Установка зависимостей и сборка
pnpm install
pnpm --filter @zcode/server build
pnpm --filter @zcode/web build

# Запуск веб-сервера
PORT=3040 ZCODE_SERVER_HOST=0.0.0.0 node packages/server/dist/entry-http.js
```

### Добавление на домашний экран (PWA на iPhone / Android)

1. Откройте выданную ссылку с токеном в **Safari на iPhone** (или Chrome на Android).
2. Нажмите иконку **Поделиться** (Share) -> **На экран «Домой»** (Add to Home Screen).
3. Запустите приложение с домашнего экрана — оно откроется в полноэкранном режиме без адресной строки браузера.

## Безопасность и дисклеймер

* **Только доверенная сеть (LAN):** данный веб-сервер предназначен для запуска в защищенной домашней сети Wi-Fi или через частный VPN (WireGuard, Tailscale, OpenVPN).
* **Не открывайте порт 3040 напрямую в публичный интернет** без HTTPS-шифрования и обратного прокси-сервера (Nginx, Caddy, Cloudflare Tunnel).
* Токен авторизации сохраняется в `localStorage` вашего PWA. Регулярно обновляйте токен при смене сети.
