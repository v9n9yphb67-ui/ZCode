## Исправленные проблемы оригинала

Оригинальный веб-интерфейс ZCode (`zcode --web`) рассчитан на десктопные браузеры и управление мышью. При использовании с мобильных устройств (iOS Safari, Android Chrome, PWA) проявлялся ряд критических дефектов. Ниже приведён список решённых проблем и применённых инженерных исправлений.

---

### 1. Ввод текста и клавиатура

* **Задержка ввода и зависания при редактировании текста в Safari**
  * *Проблема:* На каждый введённый символ или нажатие Backspace композер синхронно вызывал сохранение черновика, перерендеривая всё дерево сессии (более 4000 строк компонентов), выполнял полный обход DOM при `beforeinput` и повторно сериализовал Markdown AST. При редактировании набранного текста WebKit зависал на 1–2 секунды.
  * *Решение:* Сохранение черновика переведено на дебаунс (350 мс), добавлен fast-path для событий ввода в обход тяжелых проверок DOM, внедрён гард на композицию символов (`editor.isComposing()`), кэширован результат сериализации AST.

* **Автоматическое открытие экранной клавиатуры при навигации**
  * *Проблема:* Десктопная логика вызывала `inputApi.focus()` при монтировании страницы, переключении вкладок и открытии чатов. Экранная клавиатура мобильной ОС перекрывала интерфейс при каждом переходе.
  * *Решение:* Добавлено определение тач-устройств (`isMobileTouchViewport` для экранов ≤767px). Автофокус при старте и смене сессий пропускается. Клавиатура открывается только при явном тапе по полю ввода.

---

### 2. Мобильная вёрстка и тач-интерфейс

* **Сжатие области диалога боковыми панелями (раскладка 50/50)**
  * *Проблема:* Панели инспектора кода и браузера открывались как колонки `ResizablePanelGroup`, сжимая область чата до полосы шириной ~100px.
  * *Решение:* Контейнер панелей на мобильных экранах выведен из flex-потока (`flex: 0 0 0px !important`), а сами панели переведены в режим всплывающих оверлеев (drawers) с аппаратной GPU-анимацией выезда (`transform: translateX`), затемнением фона и кнопками закрытия.

* **Сбои закрытия сайдбара навигации**
  * *Проблема:* Автоскрытие сайдбара срабатывало только при смене идентификатора задачи, повторный выбор активной задачи не закрывал меню. Сайдбар перекрывал кнопку вызова и не имел кнопки закрытия.
  * *Решение:* Закрытие сайдбара привязано к событию выбора любого элемента навигации (`collapseSidebarOnMobileNav`), добавлен отдельный элемент закрытия (`XIcon`) для тач-режима.

* **Смещение экрана (overscroll) и масштабирование полей в iOS**
  * *Проблема:* Нативный жест скролла iOS (rubber-band) смещал весь документ за границы экрана, а поля ввода со шрифтом менее 16px вызывали нежелательное приближение страницы в Safari.
  * *Решение:* На уровне `html, body` зафиксированы `overflow: hidden`, `overscroll-behavior: none` и `touch-action: manipulation`. Размер шрифта инпутов зафиксирован на `16px !important`, включён `viewport-fit=cover`, для ленты сообщений включён momentum-скролл (`-webkit-overflow-scrolling: touch`) с изоляцией слоёв.

* **Недоступность действий сообщений и деталей ошибок на сенсорных экранах**
  * *Проблема:* Кнопки копирования и редактирования отображались только по событию `:hover`. Описания ошибок вызова инструментов выводились в тултипах, недоступных по тапу.
  * *Решение:* Кнопки действий сделаны постоянно видимыми на тач-устройствах через `@media(hover:none)`. Тултипы ошибок заменены на интерактивные компоненты `Popover`, открывающиеся по клику.

### 3. Сеть, файлы и уведомления

* **Ошибка загрузки вложений по локальному HTTP**
  * *Проблема:* Загрузка медиафайлов требовала вычисления SHA-256 через WebCrypto API (`crypto.subtle`), который блокируется браузерами в незащищённых контекстах (LAN HTTP, `http://192.168.x.x`). Загрузка прерывалась ошибкой `checksumUnavailable`. Аналогично блокировался `navigator.clipboard`.
  * *Решение:* Внедрён JavaScript-фолбэк для вычисления SHA-256, работающий без HTTPS, а также полифилл буфера обмена на базе `execCommand`.

* **Отсутствие фоновых уведомлений при работе без VPN**
  * *Проблема:* Web Push в Safari требует валидных SSL-сертификатов, недоступных при прямом подключении по IP, а настройка VPN-туннелей на мобильных устройствах не всегда удобна.
  * *Решение:* Встроен ntfy-мост. Сервер отправляет HTTP POST на указанный топик `ntfy.sh` при завершении или ошибке задачи. Уведомления поступают в бесплатное приложение ntfy даже при закрытом браузере и заблокированном экране.

---

### 4. Архитектура сервера, сохранение состояния и локализация

* **Сброс активной сессии при выгрузке страницы мобильной ОС**
  * *Проблема:* При нехватке памяти браузер выгружает фоновую вкладку PWA. Повторное открытие обрабатывалось как новый запуск и открывало пустой черновик, стирая ссылку на последнюю сессию.
  * *Решение:* Добавлен механизм `restoreOnFreshLoad: !isDesktop`, восстанавливающий последнюю активную беседу из локального хранилища при холодном старте.

* **Ограничение одним рабочим каталогом и потеря сессий по умолчанию**
  * *Проблема:* Сервер принимал только один путь в `ZCODE_SERVER_WORKSPACE`, исключая доступ к общим беседам (`default` workspace). Короткие пути Windows (8.3) вызывали сбой `fs-event` в libuv.
  * *Решение:* Добавлена поддержка нескольких каталогов через разделитель `;`, общий воркспейс бесед интегрирован в интерфейс под заголовком «Задачи», добавлена нормализация путей через `realpathSync.native`.

* **Сброс выбранной модели при переключении между каталогами**
  * *Проблема:* Выбор модели сохранялся строго в контексте одного проекта, переключение на другие задачи сбрасывало выбор на системный дефолт.
  * *Решение:* Добавлено глобальное сохранение последней использованной модели (`zcode-model-selection-recent-global-v1`), действующее для всех проектов и новых черновиков.

* **Сбой инициализации MCP-инструментов в веб-режиме**
  * *Проблема:* Медленный запуск stdio MCP-серверов приводил к фиксации нулевого количества инструментов в runtime. В интерфейсе веб-клиента список серверов оставался пустым.
  * *Решение:* Внедрён механизм `collectLateArrivals` для регистрации инструментов на последующих шагах, подключен RPC-канал `mcpSyncService` к панели настроек веб-клиента.

* **Отсутствие русской локализации**
  * *Проблема:* Интерфейс поддерживал только английский и китайский языки.
  * *Решение:* Выполнен полный перевод 5 472 строк интерфейса с выверенной терминологией, добавлен переключатель локали («Ру») в сайдбар, локаль `ru-RU` зарегистрирована в серверных схемах валидации.

## Быстрый старт

### Вариант 1. Установка готового пакета (Рекомендуется)

```bash
curl -fsSL https://github.com/v9n9yphb67-ui/ZCode/releases/download/v3.14.0-web/install.sh | sh
```

Запуск сервера:
```bash
zcode --web --host 0.0.0.0 --port 3040
```

Сервер выведет адрес для подключения:
```
http://192.168.x.x:3040/?token=YOUR_TOKEN
```

### Вариант 2. Запуск из исходного кода

```bash
git clone -b iphone-web https://github.com/v9n9yphb67-ui/ZCode.git
cd ZCode

pnpm install
pnpm --filter @zcode/server build
pnpm --filter @zcode/web build

PORT=3040 ZCODE_SERVER_HOST=0.0.0.0 node packages/server/dist/entry-http.js
```

### Добавление на домашний экран (PWA)

1. Откройте выданную ссылку с токеном в **Safari на iPhone** (или Chrome на Android).
2. Нажмите **Поделиться** -> **На экран «Домой»**.
3. Запустите приложение с иконки домашнего экрана.

## Безопасность

* **Только доверенная сеть (LAN):** Сервер предназначен для работы в защищённой локальной сети Wi-Fi или через частный VPN.
* **Не открывайте порт 3040 в публичный интернет** без HTTPS-шифрования и обратного прокси-сервера (Nginx, Caddy, Cloudflare Tunnel).
* Токен авторизации сохраняется в `localStorage` вашего PWA.
